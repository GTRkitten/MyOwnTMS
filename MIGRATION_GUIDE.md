# Руководство по миграции путей вложений

## Обзор

Это руководство описывает процесс миграции базы данных MyOwnTMS для поддержки переносимости путей к вложениям. Ранее система использовала абсолютные пути, что делало невозможным перенос базы данных на другой компьютер. Теперь система использует относительные пути с централизованным хранилищем файлов.

## Что изменилось

### До миграции:
- Вложения хранились с абсолютными путями (например: `C:\Users\User\Documents\...\screenshot.png`)
- База данных была привязана к конкретному компьютеру
- Экспорт в PDF/DOCX мог не работать на других машинах

### После миграции:
- Вложения хранятся в директории `data/attachments/` с относительными путями
- База данных переносима между компьютерами
- Все файлы автоматически копируются в централизованное хранилище
- Экспорт работает корректно на любой машине

## Подготовка к миграции

### 1. Резервное копирование

Перед миграцией обязательно создайте резервную копию:

```bash
# Копирование базы данных
copy data\tms.db data\tms.db.backup

# Или используйте встроенную функцию миграции
python migrate_to_relative_paths.py
# И выберите 'y' когда спросит о создании бекапа
```

### 2. Проверьте наличие вложений

Посмотрите в базе данных, есть ли у вас вложения:

```python

from src.database.session import get_session

session = get_session()
```

## Запуск миграции

### Вариант 1: Через скрипт миграции (рекомендуется)

```bash
# Из корневой директории проекта
python migrate_to_relative_paths.py
```

Скрипт выполнит следующие действия:
1. Создаст бекап базы данных (если вы согласитесь)
2. Скопирует все файлы вложений в `data/attachments/`
3. Обновит пути в базе данных на относительные
4. Покажет статистику миграции

### Вариант 2: Ручная миграция

Если автоматический скрипт не подходит, вы можете выполнить миграцию вручную:

```python
from src.database.session import get_session
from src.database.models import Attachment
from pathlib import Path
import shutil

session = get_session()
ATTACHMENTS_DIR = Path("data/attachments")
ATTACHMENTS_DIR.mkdir(parents=True, exist_ok=True)

attachments = session.query(Attachment).all()

for attachment in attachments:
    old_path = Path(attachment.file_path)
    
    if old_path.is_absolute() and old_path.exists():
        # Создаем уникальное имя
        new_name = f"migrated_{attachment.id}_{old_path.name}"
        dest_path = ATTACHMENTS_DIR / new_name
        
        # Копируем файл
        shutil.copy2(old_path, dest_path)
        
        # Обновляем запись
        attachment.file_path = new_name
        print(f"Мигрировано: {attachment.file_name}")

session.commit()
session.close()
```

## Что делает скрипт миграции

1. **Проверяет существующие вложения** - читает все записи из таблицы `attachments`
2. **Определяет тип пути** - проверяет, является ли путь абсолютным
3. **Копирует файлы** - перемещает все файлы в директорию `data/attachments/`
4. **Обновляет базу данных** - заменяет абсолютные пути на относительные
5. **Сохраняет изменения** - коммитит транзакцию в БД
6. **Показывает отчет** - выводит статистику: сколько файлов мигрировано, пропущено, ошибок

## Обработка особых ситуацией

### Файл не найден

Если скрипт обнаружит, что файл по указанному пути не существует:
```
[WARN] screenshot.png - файл не найден: C:\...\screenshot.png
```

В этом случае:
- Запись в базе данных остается без изменений
- Файл будет помечен как ошибка
- Вам нужно найти файл вручную или удалить запись из БД

### Файл уже в правильной директории

Если файл уже находится в `data/attachments/`:
```
[SKIP] screenshot.png - уже относительный путь
```

Это нормально - файл просто пропускается.

### Конфликт имен

Если файл с таким именем уже существует в `data/attachments/`:
- Скрипт добавит суффикс: `screenshot_1.png`, `screenshot_2.png`, и т.д.
- Оба файла будут сохранены

### Проверка результата

```python
from src.database.session import get_session

session = get_session()

for att in attachments:
```

## Часто задаваемые вопросы

### Q: Что будет с существующими файлами?

**A:** Исходные файлы остаются на своих местах. Скрипт только копирует их в новую директорию. После успешной миграции вы можете удалить старые файлы вручную.

### Q: Можно ли пропустить миграцию?

**A:** Нет, если вы хотите использовать новую версию системы. Старый формат путей больше не поддерживается.

### Q: Что если миграция прервалась?

**A:** Если миграция была прервана, запустите скрипт еще раз. Он корректно обработает уже мигрированные файлы и пропустит их.

### Q: Работает ли это на Linux/Mac?

**A:** Да, скрипт кроссплатформенный. Пути автоматически конвертируются для вашей ОС.

### Q: Что делать с большими файлами?

**A:** Скрипт автоматически копирует файлы любого размера. Для больших файлов миграция может занять больше времени.

## Технические детали

### Структура директорий после миграции:

```
MyOwnTMS/
├── data/
│   ├── tms.db              # База данных
│   └── attachments/        # Новая директория для вложений
│       ├── 20241225_143022_screenshot.png
│       ├── 20241225_143025_log.txt
│       └── ...
├── migrate_to_relative_paths.py
└── ...
```

### Изменения в коде:

1. **Модель Attachment** - добавлен метод `get_absolute_path()` для получения полного пути
2. **AttachmentService** - метод `add_attachment()` теперь сохраняет относительные пути
3. **Экспортеры** - автоматически используют абсолютные пути при экспорте
4. **GUI** - использует новый метод `get_attachments_for_export()` для экспорта
