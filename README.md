# MyOwnTMS - Система управления тест-кейсами и баг-репортами

MyOwnTMS - это некоммерческая система управления тест-кейсами и баг-репортами, разработанная по стандартам ISTQB. Идеально подходит для независимых тестировщиков, которые не входят в команду разработчиков.

## Особенности

- ✅ Создание и управление тест-кейсами по стандартам ISTQB
- ✅ Создание и управление баг-репортами по стандартам ISTQB
- ✅ Автоматическая генерация уникальных ID (TC-001, BUG-001)
- ✅ Автоматическое проставление даты создания и обновления
- ✅ Связывание артефактов между собой
- ✅ Поиск и фильтрация по статусу
- ✅ Экспорт в форматы PDF, DOCX и Markdown
- ✅ Современный интуитивный интерфейс
- ✅ Локальное хранение данных (SQLite)
- ✅ Возможность упаковки в EXE файл

## Системные требования

- Python 3.10 или выше
- Windows 10/11 (для EXE версии)
- 100 MB свободного места на диске

## Установка

### Вариант 1: Запуск из исходного кода

1. Клонируйте репозиторий:
```bash
git clone https://github.com/yourusername/MyOwnTMS.git
cd MyOwnTMS
```

2. Создайте виртуальное окружение:
```bash
python -m venv venv
```

3. Активируйте виртуальное окружение:
```bash
# Windows
venv\Scripts\activate

# Linux/Mac
source venv/bin/activate
```

4. Установите зависимости:
```bash
pip install -r requirements.txt
```

5. Запустите приложение:
```bash
python src/main.py
```

### Вариант 2: EXE файл (Windows)

1. Выполните сборку из корня проекта в активированном виртуальном окружении:
```powershell
python -m pip install -r requirements.txt
python -m PyInstaller --noconfirm --clean MyOwnTMS.spec
```

2. Запустите `dist/MyOwnTMS.exe`

## Использование

### Создание тест-кейса

1. Нажмите кнопку "Тест-кейс" на панели инструментов или выберите "Файл > Новый тест-кейс"
2. Заполните обязательные поля (пометлены звездочкой):
   - Заголовок
   - Шаги
   - Ожидаемый результат
3. Заполните опциональные поля при необходимости:
   - Предусловия
   - Постусловия
   - Окружение
   - Приоритет
   - Статус
4. Нажмите "Сохранить"

### Создание баг-репорта

1. Нажмите кнопку "Баг-репорт" на панели инструментов или выберите "Файл > Новый баг-репорт"
2. Заполните обязательные поля:
   - Заголовок
   - Шаги воспроизведения
   - Ожидаемый результат
   - Фактический результат
3. Заполните опциональные поля:
   - Описание
   - Окружение
   - Приоритет
   - Серьезность
   - Статус
4. Нажмите "Сохранить"

### Просмотр и редактирование

- Дважды кликните на артефакт для просмотра
- Выберите артефакт и нажмите "Редактировать" для изменения
- Используйте поиск и фильтры для быстрого нахождения

### Экспорт

1. Выберите один или несколько артефактов
2. Нажмите кнопку "Экспорт"
3. Выберите формат (PDF, DOCX или Markdown)
4. Выберите режим (один документ или отдельные файлы)
5. Укажите папку для сохранения
6. Нажмите "Экспортировать"

## Стандарты ISTQB

### Тест-кейс содержит:
- ID (автоматически)
- Заголовок
- Предусловия (опционально)
- Шаги
- Ожидаемый результат
- Постусловия (опционально)
- Окружение (опционально)
- Приоритет
- Статус
- Дата создания и обновления (автоматически)

### Баг-репорт содержит:
- ID (автоматически)
- Заголовок
- Описание (опционально)
- Шаги воспроизведения
- Ожидаемый результат
- Фактический результат
- Окружение (опционально)
- Приоритет
- Серьезность
- Статус
- Дата создания и обновления (автоматически)

## Форматы экспорта

- **PDF**: Для печати и отправки по электронной почте
- **DOCX**: Для редактирования в Microsoft Word
- **Markdown**: Для использования в системах контроля версий и документации

## Горячие клавиши

- `Ctrl+N` - Новый тест-кейс
- `Ctrl+Shift+N` - Новый баг-репорт
- `Ctrl+E` - Экспорт
- `Del` - Удалить выбранный артефакт
- `Ctrl+Q` - Выход
